# Agent Note: 局部切页后恢复原有状态面板

Status: implemented

## Problem

局部切页脚本可以替换 body 内容或 body 节点，移除仍在工作的 StatusPanel。应用保留状态与未完成的历史写入，但面板节点已脱离页面；只检查 `div#csp` 的可见性无法恢复挂载，关闭 csp 显示限制时也仍需处理节点移除。

## Decision

共用 StatusPanel 将 DOM 观察与 csp 可见性设置分开：观察器始终监听 documentElement 下的变化，发现原面板脱离文档时，将同一节点挂到当前 body，再按 csp 设置决定是否隐藏。body 暂时不存在时保留节点并等待后续变化。

恢复过程复用当前实例、状态、历史和异步写入身份，不重新读取历史或创建应用。`create()` 遇到已有面板时也核对挂载；渲染在判断内容缓存或清理自身 mutation 记录前先同步 DOM，避免先执行的渲染消费外部移除记录后丢失恢复机会。

`destroy()` 断开观察器并清空节点引用，既有生命周期检查继续约束迟到的设置和持久化回调。两个包的面板测试统一销毁实例，防止仍活动的观察器干扰后续用例。

## Alternatives considered

- 保持仅在 csp 显示限制开启时观察 DOM：观察范围与原设置对应，关闭限制时无需监听；但面板移除与显示限制无关，无法保证关闭限制后的恢复。
- 移除后创建新面板实例：可以复用初始化路径；但需重新协调状态、历史读取及未完成写入，新实例的身份也会改变。复用原节点可以保留这些连续性。
- 只在渲染时恢复：无需依赖观察器触发恢复；但状态没有变化时不会及时渲染，因此仍需观察器处理静默移除。渲染同步作为补充，覆盖观察回调之前消费 mutation 的时序。

## Verification

共用核心的面板回归覆盖两种 csp 设置下恢复同一节点、无 csp 时保持隐藏及后续显示、替换 body、渲染先于观察回调，以及销毁后不被渲染或持久化回调复活；同时断言恢复不重复读取或追加历史。用户脚本面板回归继续验证平台适配及异步设置。

本次提交前已执行 `mise exec -- pnpm check`，包含两个包的测试、覆盖率、类型检查及构建；提交的三份代码与测试文件和该次验证时的内容一致。新增记录通过文档格式、链接与笔记结构检查。浏览器中的实际 AADB 交互未单独执行 E2E，不将 DOM 测试视为该场景的浏览器证据。

## Consequences

面板恢复不重置状态或重复读取历史，可见性设置继续只控制显示。代价是关闭 csp 显示限制后仍保留 DOM 观察器，因此观察回调只在节点脱离或相关 csp 变化时同步，渲染继续清理自身 mutation；销毁时必须断开观察。

恢复范围是当前应用实例和当前 documentElement 内的 body 变化，不负责在应用已销毁后重新启动应用。后续修改渲染缓存、观察记录清理或异步回调时，需要保留上述时序回归。
