# Agent Note: 旧目标主动取消、模型鉴权分类与初始化计时补漏

Status: implemented

## Problem

App 忙时仅记录待扫描标记，验证码已经替换，旧初始化的信号仍未取消。身份复核能防止旧提交，却不能及时释放准备等待。模型 GET 的 HTTP 403 被包装为普通错误，同一轮会按瞬时失败重试。扩展内容客户端仍用系统时钟计算初始化持续时间，回拨后出现负耗时。

依赖审计同时发现锁定的 `brace-expansion@5.0.9` 已不能通过既有安全门禁，需要沿原主版本更新补丁，而非降低门槛或扩大升级范围。

## Decision

- App 记录活动轮次的完整目标与取消控制器。相关 mutation 到达时先复核身份，变化或移除立即取消，再防抖扫描最新目标；相同目标的子节点变化与提交按钮启用不取消。已取消的旧控制器不会再次取消新轮次。
- 准备等待复用 `raceAbort`，即使底层 Promise 不响应取消，也及时结束 App 等待；迟到成功和拒绝都不能恢复旧目标。实际底层资源回收仍由 detector 的取消契约负责。识别与提交继续串行，并复用原有信号检查及控件身份复核。
- 模型 GET 的 403 转为现有 `ModelAccessKeyRejectedError`，与额度查询、确认的永久错误分类一致；先检查调用方取消和期限，错误正文只尽力清理。凭证提交后的恢复入口不变。
- `RemoteDetectorClient.prepare()` 在同一内容页面使用 `performance.now()` 并取整；静默、取消、超时和销毁路径不写入就绪耗时，不改变历史本地时刻或服务端额度时间。
- 仅将 `brace-expansion@5` 的 override 下限和锁定版本升级到 `5.0.12`，保留最低发布年龄、主版本边界与审计门槛，其余依赖不变。

### 既有决定检索

检索非归档 lifecycle 的取消、403、时钟和安全补丁主题。[验证码恢复与手动答案](2026-09-22-captcha-recovery-and-manual-selection.md)覆盖目标发现和凭证恢复，本篇补足发现之后的即时取消；[有界流与生命周期](2026-09-29-bounded-io-and-lifecycle.md)已统一核心推理计时，本篇补上扩展内容客户端；[测试工具链安全](2026-09-29-test-toolchain-security.md)保留原验证时点，本篇只追加后续定向补丁。三篇部分重叠但不取代；未发现需要吸收或废弃的相关 proposed/rejected 记录。

## Alternatives considered

- 等旧准备完成后只丢弃结果：实现简单、可继续共享初始化，但新验证码仍被旧请求期限阻塞，未选。
- 任意 mutation 都取消，或并发启动多个 Solver：前者易被页面自身变更反复中断，后者破坏单次提交和答案归属；仅取消身份变化的活动轮次并保持串行。
- 所有 HTTP 失败都归为永久错误：减少请求，却阻断网络和服务端瞬时故障的既有恢复；只补齐明确的 403 分类。
- 将负耗时截断为零：保持旧时钟来源，却仍错误计入时钟前跳；改用单调时钟。
- 全量更新工具链或忽略公告：前者扩大回归面，后者绕过安全门禁；采用同主版本最小补丁。

## Consequences

旧初始化不再阻塞新目标，403 不触发同轮瞬时重试，扩展初始化耗时不再受校时影响。取消不承诺撤销已经提交的缓存、服务端确认或浏览器副作用；就绪会话及其他消费者仍按现有共享规则处理。连续真实目标变化可能增加被取消的准备次数，这是最新目标优先的代价。

回归覆盖 body 移除、快速连续换图、同 URL 控件替换、action/formaction 变化、同目标 mutation、准备迟到成功/拒绝、提交等待取消、凭证恢复、403 清理挂起以及双向系统校时。文档漂移测试拒绝把架构与缓存契约移到 README 后冒充专题仍完整。验证使用本地测试绑定和 fixture，不代替生产 Key、真实模型鉴权或 Firefox Android 外部证据。
