# Agent Note: 保留人工撤销并恢复同页验证码处理

Status: implemented

## Problem

同一验证码因提交按钮不可用而重试时，旧自动答案仍会参与合并；用户在异步识别或点击等待中取消该答案，稍后的自动点击可能把它勾回。App 的观察器绑定初始 body，整体替换 body 后面板能够恢复，但新验证码不再触发扫描。用户脚本在缺少或无效 Key 时记录永久失败，随后菜单成功保存有效 Key，却没有通知 App 重试当前目标。

## Decision

保留模式将本轮人工变更身份覆盖到模型准备、图片读取、推理、设置读取及多选等待。初始裁剪不计算本轮已经手动取消的候选，每次自动勾选前再次核对，不能因旧自动标记或识别结果而恢复用户取消的选项。新一轮重新捕获身份，关闭保留模式继续由程序接管。

App 在稳定的 documentElement 观察目标相关 mutation，保留防抖、去重和目标快照。body 替换或暂时缺失后重插仍触发扫描，销毁后不响应。StatusPanel 独立保留原节点、状态与历史。

用户脚本以 GM Key 的实际存储提交驱动恢复。菜单保存、清除和留空清除成功后，先取消并等待旧的未完成模型初始化，再通知 CoreApp 恢复当前目标；已就绪会话继续使用。依赖组装层以提交修订号与销毁状态屏蔽旧回调，取消输入、验证失败或存储失败不触发恢复。HEAD 验证成功的提示只说明 Key 已验证并保存，不声称下载过模型。

2026-10-23 的[编码长度与状态边界修复](2026-10-23-audit-boundaries-and-encoding.md)以认证 `GET /quota` 替代 HEAD 长度验证；本篇的实际提交、取消与恢复所有权不变，以下证据保留原日期含义。

## Existing record audit

检索非归档决定中的答案、人工、body、面板、Key 和恢复：[面板挂载](2026-09-16-status-panel-remount.md)部分重叠，本篇补足独立答题扫描；[BFCache 断连](2026-09-18-extension-port-disconnect-errors.md)仍约束扩展连接，不自动重放下载或 Key 操作，均保留。

## Alternatives considered

- 只在提交等待结束后读取选中项：能够保留最后一次人工修改，但此前自动点击已经可能覆盖取消操作，必须从本轮开始跟踪。
- 永久记住取消的 checkbox：无需轮次身份，但同一 DOM 用于下一验证码时可能持续屏蔽合法候选；保护限定在本轮。
- body 替换后重建整个 App：可重新启动扫描，但会丢失当前面板和异步写入身份；稳定父节点观察保留既有实例。
- 保存 Key 后要求刷新：实现成本低，但用户已在当前页面修正凭证；明确的提交回调可以恢复当前失败目标，同时保护销毁和并发提交。
- 每次 Key 变化都销毁已就绪推理会话：能统一重建流程，但会增加初始化和缓存访问；只有未完成的准备依赖旧 Key，已就绪会话继续复用。

## Verification

核心回归使用真实 App、CaptchaSolver 和 AnswerSubmitter，覆盖失败后重试期间各异步阶段人工取消、初始裁剪、关闭保留模式、body 替换、旧目标失效与销毁。用户脚本回归经过实际 App 组装、GM 菜单和核心推理客户端，覆盖成功提交、保存失败、取消输入、验证失败、并发提交、旧准备取消、迟到响应、销毁和就绪会话复用。

本地用户脚本与扩展内容脚本浏览器 E2E 验证共享答题和页面生命周期集成，不代表真实 GM 管理器、线上 Key 鉴权或实际 AADB 页面验收。

## Consequences

尊重人工撤销可能使候选少于模型结果，数量目标不能推翻撤销。扩大观察至 documentElement 后仍过滤相关 mutation。GM 提交与恢复分阶段：恢复等待或应用销毁均不撤销已保存 Key。
