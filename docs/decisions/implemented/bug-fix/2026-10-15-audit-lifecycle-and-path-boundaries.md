# Agent Note: 验证竞态、连接失效与笔记路径边界

Status: implemented

## Problem

全仓离线审计确认九项缺口：用户脚本旧 Key 验证晚到可覆盖清除/新设置；Offscreen 新 epoch 接管已空闲文档后停止通知、取消创建后文档无人接管；仅修改验证码选择器属性不补扫；IndexedDB 异常关闭后持续复用失效连接；笔记根或祖先链接可让归档基线检查误判为仓库外；pnpm 声明不一致；内部额度成功响应接受 null 回执；Worker 配置测试复制本地生成配置和状态。

## Decision

1. 用户脚本用意图代次淘汰尚未写入的旧验证，成功、额度耗尽及失败分支都复核代次。取消输入保留原操作；已发起的 GM 写入按实际提交结算，不声称回滚。
2. Offscreen 新 epoch 迁移同一空闲代际的通知，保留次数和退避预算；确认不等于关闭成功。取消创建的迟到准入仍以现有超时独立 claim，释放 admission 后允许空闲回收，不重放业务请求，不取消并发活跃请求。
3. App 观察 `id/name`，发现条件补齐时补扫；条件移除时按旧活动目标判断相关性，立即取消，再防抖恢复。
4. IndexedDB 的异常 `close` 与 `versionchange` 共用连接身份校验和生命周期失效；取消事务、共享下载与确认，下次操作重新打开，旧连接迟到事件不得影响新连接。
5. 笔记根和所有祖先须为真实目录，包装器及直接验证/封印入口均失败关闭。CI 事件 JSON 读取/解析失败输出固定诊断，不暴露原始片段；不改既有封印。
6. 按维护者选择将 mise、当前文档和版本契约同步到 pnpm `12.11.2`，保留原有 packageManager 修改；Node 版本不变，历史决定和审计不改写版本证据。
7. 内部额度响应先确认回执为字符串，再验证规范化结果；非字符串按依赖失败处理，不生成 `null` 回执头。
8. 配置测试仅复制模板与四个必需脚本。公开哨兵验证生成配置、环境文件和 `.wrangler/` 状态不进入临时目录，不用真实秘密验证隔离。

检索非归档 lifecycle 后，[上次边界修复](2026-10-14-audit-regression-hardening.md)、[Key 大小写与取消](2026-10-12-audit-follow-up.md)、[测试归属](../testing/2026-10-14-test-suite-ownership.md)和[历史工具链安全](2026-09-29-test-toolchain-security.md)部分重叠，保留原决定与验证时点。本篇补充后续边界，不翻转产品、发布或测试归属；没有需吸收或废弃的相关 proposed 记录。

### 2026-10-22 复核补充

后续源码与本地故障注入确认十项剩余边界，不翻转上述决定：

1. 扩展秘密数据库也监听异常 `close`，与 `versionchange` 共用连接身份检查和未决事务失效，下一次操作重新打开；旧连接事件不能关闭新连接。
2. 处理中仅 URL 变化时，旧 App 轮次停止点击并在结算后补扫当前有效目标；不引入全局 history API 覆写或轮询。Solver 保留 detect 永久错误分类，App 不以普通冷却或按钮启用解除抑制。普通失败的计时全部使用 `performance.now()`。
3. 普通设置首次加载前，用户是否编辑过字段与字段当前值分离；改回初始显示值仍保留输入身份，加载完成后再按真实持久化基线计算脏状态。
4. Release 不再先查询标签是否缺失，而是在全部门禁后原子创建绑定 `GITHUB_SHA` 的标签，再以 `--verify-tag` 发布。已有标签和 API 失败均停止；后续发布失败不自动删除或改绑已创建标签。
5. Action 门禁对 flow 显式 `uses` 键校验或明确拒绝，不能静默跳过。浏览器危险调用门禁同时拒绝 `Function()` 和 `new Function()`，不增加白名单。
6. 直接归档入口区分真实仓库外与 Git 发现失败；配置、权限或查询错误不能跳过历史基线，也不能写封印。模型清单解析检查完整对象 initializer，拒绝对象后的继续求值，只接受约定的字面量与 `as const`。

回归保留真实行为边界：数据库重开和旧事件、URL-only 自动接手、跨层永久错误、校时下冷却、首次加载编辑、发布失败关闭、CLI 负例和实际清单身份。静态门禁通过不代替这些故障注入。

## Alternatives considered

- 只在提交回调仲裁 Key：无法阻止验证完成后已经发起的旧写入；必须在写入前核对。
- 取消后直接关闭 Offscreen，或每次接管重置预算：前者会干扰并发请求，后者会恢复无限重试；沿用 admission 与有界 claim 更安全。
- 仅捕获失效数据库事务：仍会持续缓存坏连接；应在 close 事件清除身份并取消生命周期。
- 跟随笔记链接再检查哈希：攻击者可连同清单重算，Git 基线不能变为可选；目录身份必须先校验。
- 测试复制整个 Worker 再过滤秘密名：新增状态目录容易漏排；固定源码白名单不接触本地配置。

## Consequences

补充验证晚到、接管/取消、选择器增删、数据库重开及旧事件、异常回执、链接根/祖先与不改封印的回归。生命周期事实加入所属专题的文档漂移负例；测试绑定配置由仓库外备份并按字节恢复。

GM 已发起写入不能撤销；Offscreen 的通知预算仍有限，持续平台故障后可能暂时驻留。符号链接形式的笔记路径现在直接拒绝，维护者需提供实际目录。完整验证遵循[验证手册](../../../development/verification.md)；本地单测与离线浏览器证据不代替真实 Key、最低浏览器版本、Android 或远程 CodeQL。
