# Agent Note: 有界流读取与销毁后的副作用边界

Status: implemented

## Problem

全仓库风险审计发现：验证码 HTTP/头校验失败与 Model Worker R2 拒绝路径会等待 `ReadableStream.cancel()`；取消 Promise 永不完成时，已有请求超时不能释放这些等待。模型下载、额度查询、验证与确认也会因等待清理把已有 HTTP 错误改写成超时。未知长度读取保存全部分块引用，字节上限不能限制空分块对象数量或分块所引用的大缓冲。

扩展设置镜像只在入队时检查销毁，排队写入或删除可能在 BFCache 旧实例销毁后继续启动。用户脚本 Runtime 长度头使用 `Number()`，接受空值、指数等非规范表示。推理客户端的阶段计时使用系统时钟，校时后可显示负耗时。

## Decision

- 浏览器复用 `cancelByteStream`，Worker 保留本层的尽力清理函数；发起取消但不等待取消 Promise，同时处理同步抛错和异步拒绝。HTTP、完整性与调用方取消仍由原业务路径决定，不伪称底层资源已完成释放。
- `readBoundedByteStream` 对已知长度直接预分配；未知长度使用上限内按需倍增的自有缓冲，即时复制、忽略空分块、返回时裁剪。验证码图片复用该原语，删除重复读取/清理实现；保留 MIME、字节上限、声明/实际长度、非空和取消校验。
- 镜像每次真正调用存储前重新检查生命周期。销毁阻止尚未开始的写入/删除；已发起调用仍按真实结果结算。预先取消的初始化不监听、不读快照。排队 Promise 仍随已有串行尾链结算，不宣称对浏览器存储提供事务撤销。
- Runtime 的长度头只接受规范十进制安全整数并检查上限。`Content-Length` 是线上编码长度，fetch 正文可能已解压且 Content-Encoding 未经 CORS 暴露，故不要求它等于清单原始长度；实际解码正文仍执行精确长度和 SHA-256 校验。
- OnnxWorkerClient 初始化、推理阶段统一用 `performance.now()` 并取整；不改变历史本地时刻、月度额度、缓存期限的时钟语义。

## Alternatives considered

- 给取消再加独立超时：能限制挂起，但每次已知失败仍额外等待，并引入另一套期限；拒绝路径无需清理成功才能返回。
- 未知长度直接分配最大缓冲：实现短，但小图片和诱饵响应也占最大空间。保留分块数组虽减少增长复制，却不能约束对象数量或底层引用，未选。
- 销毁时取消全部存储 Promise：能让调用方立即结束，却不能撤销已经发起的 `storage.local` 调用；保留真实结算更准确。
- 长度头直接等于清单长度：未压缩资源检查更强，但误拒正常 CDN 压缩响应；实际正文完整性仍是最终依据。
- 全部 `.then()` 改成 async/await 或把短生命周期超时改成 alarms：不解决上述问题，也会扰动串行尾链、清理与兼容版本；不做机械改写。

## Consequences

故障返回不再由清理是否完成决定；旧镜像不能启动未提交副作用。未知长度流的保留内存随字节上限而非分块个数增长，但增长/裁剪时仍有临时双缓冲，未宣称整个进程内存峰值等于上限或实测吞吐提升。有限时间内持续产生空分块的 CPU 开销仍受调用方期限约束，不是流实现安全证明。

负向回归先复现挂起、旧队列写入、长度头解析及回拨计时，再验证修复；测试也覆盖分块缓冲复用、空/小分块、压缩长度差异与已启动写入的真实结算。定向测试、全仓库检查与浏览器证据记录在[本轮审计](../../../audits/2026-09-29-web-extension-audit.md)。不改变权限、模型身份、消息 schema、额度规则、依赖版本或发布流程。
