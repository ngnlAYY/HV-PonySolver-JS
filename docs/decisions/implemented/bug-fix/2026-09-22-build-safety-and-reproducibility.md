# Agent Note: 保护构建清理目录并固定跨时区归档

Status: implemented

## Problem

ORT 构建根只校验目录名、符号链接与 inode。合法的自定义构建根若包含仓库或初始工作目录，正常清理 `js-build` 或模型中间目录仍会删除用户源码。扩展 ZIP 固定为 UTC 的 1980 年时间点，但归档器按本地日历字段编码；负时区会落到 ZIP 不支持的 1979 年，其他时区则产生不同字节。

线上 [Repository CI 运行](https://github.com/ngnlAYY/HV-PonySolver-JS/actions/runs/35313103889/job/105498999041) 在安全审计阶段失败。锁定的 `sharp 0.35.3` 受 [GHSA-rgj7-g3m4-5g8c](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c) 影响，后续构建和测试被依赖条件跳过，不能将它归因于打包代码错误。

## Decision

ORT 入口先规范化仓库、初始 cwd 和 home，并拒绝覆盖这些路径的构建根及仓库内的构建目录。每次递归删除前仍核对根身份和所有目标路径，禁止符号链接、越界或覆盖受保护目录。初始 cwd 在启动时固定，正常构建随后进入 ORT checkout 不改变保护对象。

扩展归档固定本地日历字段 `1980-01-01 00:00:00`。fflate 使用这些字段生成相同 DOS 时间，不再由机器时区转换 UTC 时间点；排序、有界压缩和增量哈希保持不变。

工作区将 sharp override 的最低版本提升到修复版本 `0.35.4`，同步锁文件和关联二进制依赖。保留 `audit:high` 阈值、受保护发布条件与现有工具链，不忽略该公告或放宽安全门禁。

## Existing record audit

检索非归档决定中的 ORT、清理、ZIP、时区、sharp 和安全审计，没有已有同主题决定。[文档重建决定](../process/2026-09-16-documentation-rebuild.md)只约束契约归属；[Runtime 专题](../../../onnx-runtime.md)与[扩展专题](../../../browser-extension.md)已有清理与可重复构建契约，本篇补齐实现边界，不改变模型身份、产品版本或发布模式。

## Alternatives considered

- 只要求调用者选择空目录：实现简单，但不能满足递归清理必须保护仓库、cwd 和 home 的约束；临时目录同样可能包含源码。
- 只在入口校验构建根：足以拒绝最初的重叠配置，但不能覆盖后续路径变化，因此每次删除前继续复核。
- 在 CI 中设置 UTC 时区：能够让该环境构建成功，但本地其他时区仍失败或产生不同 ZIP；固定归档字段直接保护产物契约。
- 临时降低审计阈值：能够使后续 job 运行，但会保留已知高危依赖；采用上游修复版本并保留原门禁。

## Verification

ORT 测试运行真实 shell 入口，验证构建根包含仓库或初始 cwd 时在创建锁之前拒绝，源码标记保留；路径测试覆盖符号链接、越界、祖先变化和切换 cwd 后的合法清理。ZIP 测试在 UTC、上海、纽约和檀香山子进程调用真实归档函数并比较完整字节及 SHA-256。

依赖验证使用冻结安装、安全审计与 Model Worker 测试，并由完整项目检查覆盖构建集成。上述本地证据不代表远程 CI 已重新执行，也不包含大型 ORT 编译、生产模型服务或发布操作。

## Consequences

自定义 ORT 构建目录若与仓库或启动路径重叠会提前失败，需要移到独立位置。跨时区归档恢复确定性，但非 UTC 机器生成的旧 ZIP 校验值可能与修复后的新产物不同；发布证据必须绑定重新生成的实际 ZIP。安全修复只更新相关依赖树，不借此升级其他工作区或改变客户端版本。
