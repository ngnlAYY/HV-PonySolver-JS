# Agent Note: 按实现归属精简测试与完整检查去重

Status: implemented

## Problem

用户脚本迁移到 browser-core 后，仍重复验证大量共用实现；新回归又覆盖了一批旧的单一成功场景。文档门禁为同一关键词循环反复复制仓库、启动扫描，清单共有字段负例重复四种组合。完整 `check` 先跑普通工作区测试，再以覆盖率模式重跑，放大等待、资源争用与时序敏感测试成本。

目标是减少真实执行和维护负担，不以用例数、行覆盖率或单次绿灯代替契约完整性。

## Decision

1. 共用行为归 browser-core；用户脚本保留 GM 存储/菜单、依赖注入、Worker/Runtime 平台与定时适配。删除重复的 App、答题、推理、下载、历史和面板用例，不改变生产代码。
2. 核心与扩展仅移除已有更强回归或相同行为分区覆盖的用例。必要断言放入已经执行相同操作的保留用例，不把不同场景藏进一个循环。保留手动选择归属、有效禁用、目标快照、各取消时点、缓存写入身份、秘密隔离、来源校验及最近审计回归。
3. 文档逐词循环按校验分支和所属专题选代表负例，保留逐篇拒绝、README 不能补足专题、源码提取、状态/事实伪装和归档封印回归。仅精简测试数据，不删文档门禁中的契约列表。两个基本 GET 行缺项由已有的“附注不能补足行内事实”回归覆盖。
4. 共有清单字段的负例保留 Chromium/remote 与 Firefox/packaged 两种后台形态；四种有效组合以及构建测试中的权限、CSP、模型身份差异仍保留。危险 HTML、特权边界、真实产物审计和浏览器矩阵不缩减。
5. packaged WASM 两种浏览器 scheme 单测使用八字节确定性输入和对应测试清单，仍走真实 loader、有界读取、长度与 SHA-256 校验。真实 WASM 文件身份归构建审计和 E2E，不在适配单测重复读取和哈希完整资产。
6. 根包新增 `test:root`，统一执行带引号的 `scripts/**/*.test.mjs`。`test` 仍包含工作区普通测试及根级测试；`check:quick` 行为不变。完整 `check` 只跑工作区覆盖率测试与根级测试各一次，保留原有静态、打包、包体和构建门禁。增加检查链回归，防止去重时漏掉根级 Node 用例或其他 quick gate。
7. 覆盖率 provider、include、阈值、CI job、E2E 和依赖不变，不添加 skip/todo。检查保留的模型缓存负例时补足 `confirmationPending: false`，确保其进入元数据/哈希分支，而非被旧记录兼容门槛提前拒绝。

## Alternatives considered

检索活跃生命周期后，[测试工具链安全](../bug-fix/2026-09-29-test-toolchain-security.md)、[MV3 边界](../bug-fix/2026-09-29-extension-mv3-boundaries.md)、[文档重建](../process/2026-09-16-documentation-rebuild.md)及[最近审计修复](../bug-fix/2026-10-14-audit-regression-hardening.md)部分重叠。保留其实现约束和历史证据，本篇改变测试归属与重复执行策略，不推翻安全决定；无须吸收或废弃的同主题 proposed/rejected 记录。

- 整批删掉低行覆盖贡献测试：会丢失相同代码行上的不同取消时点、安全输入和并发交错，未采用。
- 降覆盖率门槛、扩大超时、跳过慢用例：掩盖缺口或资源问题，未采用。
- 将全部用例合并进少量大测试：数字下降但工作量不降，且定位更差，未采用。
- 完整检查只保留 `pnpm -r test:coverage`：遗漏根级 Node 测试，未采用。
- 合并 CI test/coverage-build job：涉及独立状态检查、发布授权与 artifact 依赖，本次不改。两种 CI job 的测试数量随本次删减下降，但 job 间重复执行仍存在。

## Verification

三路隔离实现后的独立只读复核通过；定向单测、文档回归、完整 `pnpm check`、Actions SHA 门禁、32 个变更脚本/测试文件的主动 LSP 诊断及 `git diff --check` 均通过。覆盖率门槛未改：核心行覆盖率 92.62% → 92.66%，扩展 90.53%、用户脚本 91.52% 均未下降。Worker 测试配置在仓库外备份，结束按字节恢复；未暂存、提交或推送。

按 runner 展开的实际用例计数，不以 `it` 声明数量计算：

| 测试层              | 精简前 | 精简后 | 净减少 |
| ------------------- | -----: | -----: | -----: |
| 用户脚本 Vitest     |    238 |    160 |     78 |
| browser-core Vitest |    551 |    530 |     21 |
| 扩展 Vitest         |    298 |    276 |     22 |
| 扩展 Node           |    184 |    144 |     40 |
| 根级 Node           |    357 |    317 |     40 |

其余用例未删；合计删除 202 个，新增 1 个检查链回归，普通测试集合 1857 → 1656，测试代码净减少 2029 行。覆盖率链仍按原方式额外校验 9 个扩展打包脚本用例，因此不能把完整检查执行总数当独立用例数。完整 `check` 中计入重复运行的执行总数 3366 → 1665，减少 50.5%。

最近同代码成功基线耗时 228.7 秒，本次 188.0 秒，均为工作区串行、Vitest 两个 worker；负载不同，约 18% 降幅仅作单次参考。本轮未修改的旧流程基线另在真实 WASM 单测触发五秒超时，失败记录保留，不将其耗时算作加速收益。没有提高超时或绕过失败用例；两种 WASM scheme 均在精简后通过。

本次只改测试、开发检查链及文档；浏览器 E2E、真实 Key、最低版本、Android、远程 CI/CodeQL 未重跑，不能沿用上一轮结果作为本次执行证据。

## Consequences

减少共用实现的重复场景和静态事实的重复扫描；完整本地检查不再运行两轮工作区测试。应用单包测试不再承担共用实现完整证明，改动共用代码须运行 browser-core；跨包改动仍执行完整检查。以后出现新行为分区或缺陷时补充针对性回归，不以本次删减数量限制测试增长。

完整资产验证和浏览器 E2E 未被单测 fixture 替代；覆盖率通过也不证明真实 Key、最低浏览器版本、Android 或远程 CodeQL 已验证。耗时对比须区分单次测量、资源争用和失败基线，不把一次更快运行称为稳定性能保证。验证遵循[验证手册](../../../development/verification.md)。
