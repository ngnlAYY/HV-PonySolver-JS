# Agent Note: 按读者任务重建文档与契约归属

Status: implemented

## Problem

README 同时承担安装说明、源码导航、资产身份、HTTP 矩阵、全部命令和发布操作。重复契约分散在多处，使用者需要跨过维护细节才能找到设置入口；漂移检查又把这些细节固定在 README，使正文难以收敛。历史审计与日常开发说明混用，容易把过去的测试结果当作当前证据。

## Decision

README 提供产品选择、最短构建路径和文档入口。使用说明归入 `docs/usage/`，精确 HTTP 协议归入 `docs/reference/`，命令和发布步骤归入 `docs/development/`；既有四篇专题保持路径。架构页解释职责、所有权和失败路径，审计记录保留原日期、数字及未验证范围。

每种受保护契约对应一篇明确的维护文档，现有漂移检查与故障注入测试一起迁移到该文档，不拼接全部正文以掩盖缺项。命令校验覆盖新维护页，链接与笔记结构进入同一文档检查入口。

宿主要求新增维护资料放入 `docs/` 主题目录，且 `.agents` 当前整体被 Git 忽略。因此可交付的决定记录采用 `docs/decisions/{lifecycle}/{class}/日期-主题.md`，沿用技能的生命周期、六类分类和正文约束；不更改本地工具忽略规则，不建立笔记 INDEX。

## Alternatives considered

- 保留大 README、只修错字和增加目录：已有检查可原样复用，改动最小；但不能解决使用入口被协议细节淹没，以及同一契约多处重复维护的问题。
- 把全部文档统一改成决策 Note：能强制记录取舍；但安装、参数和 API 参考需要直接可执行的说明，历史审计也不能伪装成仍然有效的新决定。
- 全部重命名到新的主题树：目录一致性更强；但四篇已有专题有稳定链接和检查器入口，收益不足以抵消迁移成本，故只新增缺少的主题目录。

## Verification

验证入口为 `mise exec -- pnpm docs:check`、`mise exec -- node --test "scripts/docs-drift/test/*.test.mjs"`、格式、lint、根级 Node 测试与 Action 固定检查。故障注入覆盖专题缺项不能由 README 补足、缺失 HTTP 文档、指南内不存在的包命令、笔记状态/分类/必需节和归档重新计算封印后的篡改。

笔记检查采用技能的结构、格式、封印脚本，放在 `scripts/docs-drift/notes/`，项目包装器指定文档根并拒绝缺失 Git 基线。CI 的 guardrails checkout 读取完整历史，PR 比较 base SHA，push 比较 before SHA；本地和没有前后版本对的手动检查比较 HEAD。归档既检查文件哈希，也禁止修改或删除变更前已有的封印。

本次重建不重新认证历史报告的业务或浏览器结果；没有执行生产模型下载、远程鉴权、Android 验收或部署。原有面板源码与两份测试按开始时的字节核对，文档中的恢复挂载语义保持。

面板行为的独立取舍见[局部切页后恢复原有状态面板](../bug-fix/2026-09-16-status-panel-remount.md)，该决定不改变本篇的文档归属规则。

## Consequences

README 只承担入口，精确契约可以在所属专题内独立维护；已有负向回归随正文迁移，新增指南的命令也受检查。代价是导航、文档路径清单、检查器和测试需要同步维护，笔记校验脚本成为仓库工具，CI 获取完整历史增加检出成本。

历史报告保持原证据，旧实施入口继续导航到带日期记录。四篇既有专题保留 URL；新目录只补足使用、参考和决定分类，不强制重命名全部页面。需要新增契约或移动正文时，先调整该领域的事实读取和回归，不退回拼接全部正文或无限增长 README。

复制命令的检查只覆盖当前维护文档中的标准行内代码与 shell fenced block，不执行命令，也不解析任意 shell 程序。链接门禁不验证外部网站；时序和选择理由仍需语义审阅。后续如引入新的 Markdown 语法、发布产品或平台，必须重新评估导航与检查覆盖。
