# Agent Note: 按读者任务重建文档与契约归属

Status: implemented

## Problem

README 混合安装、源码、资产、HTTP、命令和发布；重复契约又被漂移检查固定在入口，妨碍精简。历史审计与日常手册混用，容易把过去的测试结果当成当前证据。

## Decision

README 只提供产品选择、最短构建、默认体验与入口。使用说明归 `usage/`，协议归 `reference/`，命令与发布归 `development/`；四篇既有专题保持路径。架构解释职责、所有权和失败路径；审计保留日期、数字和未验证范围。

受保护契约逐篇检查，迁移正文时同步事实读取与故障注入，不拼接文档补足缺项。当前指南的命令、链接与笔记结构进入统一文档检查；R2 复制命令直接验证远程参数和工作区相对路径。

可交付决定放在 `docs/decisions/{lifecycle}/{class}/日期-主题.md`，沿用 `write-notes-like-deepseek` 的生命周期、六类分类与正文结构；`.agents` 继续作为被忽略的本地目录，不建 INDEX。归档逐条核对清单、普通文件身份和字节哈希，拒绝 symlink；异常清单下 `--write` 不改内容或封印。

2026-10-12 继续按此分工精简全部维护文档：合并重复操作，保留前提、故障、安全和证据边界；核对工作区当前实现，包括已有 JPX 扫描恢复。历史迁移表省略重复目录前缀，路径映射和原验证数字不变；不改业务代码、文件路径或门禁以迁就正文。

## Alternatives considered

- 只修大 README 的错字与目录：改动小、检查可复用，但重复契约和入口混杂仍在。
- 所有文档改成决定 Note：取舍结构统一，但安装/API 需要直接操作说明，历史审计不能伪装成新决定。
- 全部专题迁入新目录：层级一致，却破坏稳定链接和检查器入口，收益不足。
- 只验扫描到的归档：实现短，但可能遗漏被 symlink 或同名目录替换的封印；必须逐条核验清单。

## Verification

验证入口为 `mise exec -- pnpm docs:check`、`mise exec -- node --test "scripts/docs-drift/test/*.test.mjs"`、格式和差异检查；改检查器时还需 lint、根级测试与 Actions 固定检查。

重建回归覆盖专题缺项不能由 README 补足、缺失 HTTP 页、错误包命令、R2 参数/路径、笔记状态/分类、归档篡改及 symlink/目录替换。笔记脚本在 `scripts/docs-drift/notes/`，包装器指定 docs 根并拒绝缺失 Git 基线；CI 读完整历史，PR 比 base SHA，push 比 before SHA，本地及无前后版本对的手动检查比 HEAD。已有封印不能修改或删除。

文档整理不重新认证历史业务/浏览器结果，也不执行生产下载、远程鉴权、Android 验收或部署。原重建保留的[面板恢复决定](../bug-fix/2026-09-16-status-panel-remount.md)与本次保留的 [JPX 恢复](../bug-fix/2026-10-04-jpx-ajax-scan-recovery.md)均独立维护其行为证据。

## Consequences

入口更短，精确契约有固定归属；代价是导航、路径清单、事实提取和回归需同步，笔记校验与完整历史检出增加维护成本。历史证据和四篇专题路径稳定，新增内容按职责归档。

命令检查只解析标准行内代码和 shell fenced block，不执行任意 shell；链接门禁不验证外站，时序与取舍仍需审阅。新增 Markdown 语法、产品或平台时重新评估覆盖，不退回无限扩张 README 或拼接全文的检查方式。
